# 04 — Campaigns Domain

## Objective

The Campaigns domain answers:

> Given merchant assumptions and a proposed campaign, what is the expected economic outcome?

## Main Flow

```text
CampaignDraftDTO
      ↓
CampaignSimulationService
      ↓
HistoricalDataRepository
      ↓
SimulationInputDTO
      ↓
CampaignSimulationStrategyFactory
      ↓
CampaignSimulationStrategy
      ↓
SimulationResultDTO
```

## CampaignDraftDTO

Transport/domain boundary object representing the merchant's requested campaign.

Contains:

- merchant ID
- audience size
- fixed campaign cost
- campaign type
- campaign parameters
- optional campaign conversion rate

## MerchantProfileDTO

Historical assumptions for a merchant:

- merchant ID/name/currency
- average order value
- gross margin
- historical conversion rate
- historical campaign lift
- points cost
- points redemption percentage
- points earned per currency

## SimulationInputDTO

Fully resolved input used by a campaign strategy.

Unlike `CampaignDraftDTO`, it contains the merchant-derived economic assumptions needed by the strategy.

## CampaignSimulationService

Responsibilities:

- load merchant profile;
- calculate expected campaign conversion;
- generate preset scenarios;
- create fully populated simulation inputs;
- delegate simulation to the selected strategy.

It does not implement campaign-specific incentive math itself.

## Scenario Generation

Preset scenario conversion rates are based on:

```text
campaign conversion =
historical conversion × (1 + adjusted historical lift / 100)
```

Scenario lift multiplier:

| Scenario | Historical lift multiplier |
|---|---:|
| Conservative | 0.5 |
| Expected | 1.0 |
| Strong response | 1.5 |
| Custom | Explicit rate |

For example, with 4.8% historical conversion and 42% historical lift:

```text
Expected = 4.8 × (1 + 42 / 100)
         = 6.816
         → 6.82%
```

## Strategy Pattern

### PercentageDiscountStrategy

Calculates incentive cost as a percentage discount applied to campaign orders.

### DoublePointsStrategy

Calculates incremental points generated by the bonus multiplier, then estimates their expected cost using:

- points earned per currency;
- points redemption percentage;
- points cost per unit.

## Shared Result Assembly

`AbstractCampaignSimulationStrategy` calculates:

- baseline orders;
- campaign orders;
- incremental orders;
- incremental revenue;
- incremental contribution;
- net impact;
- ROI;
- health status;
- insight.

## Health Status

Three statuses exist:

- `healthy`
- `caution`
- `risky`

Current rule:

- Healthy requires positive net impact and campaign conversion at least 1.2× break-even conversion.
- Caution applies when break-even is reached but the safety margin is small.
- Risky applies when the campaign remains below break-even.

## Calculation Trail

The result can be turned into a step-by-step explanation without knowing which strategy produced it.

This is an intentional Open/Closed-style design: adding a new strategy should not require rewriting the calculation-trail consumer as long as it produces the established result DTO.
